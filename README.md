# দুর্গা সমিতি ওয়েবসাইট (ডেমো)

এই প্রজেক্টটি HTML, CSS ও JavaScript দিয়ে তৈরি একটি Responsive বাংলা/মিশ্র-লেবেল ওয়েবসাইটের প্রথম সংস্করণ। প্রতিটি HTML পেজের CSS তার নিজস্ব `<style>` ট্যাগে আছে। সাধারণ UI/ডেটা লজিক `js/` ফোল্ডারে রাখা হয়েছে।

## চালানোর নিয়ম
1. ZIP ফাইলটি Extract করুন।
2. লোকাল কম্পিউটারে `Index.html` (অথবা `index.html`) ফাইল ব্রাউজারে খুলুন। সব ব্রাউজারে Local Storage ও ফাইল ব্যবস্থাপনার নির্ভরযোগ্যতার জন্য VS Code-এর Live Server বা অন্য সাধারণ static server ব্যবহার করা ভালো।
3. ডেমো অ্যাডমিন: নাম `আকাশ কর্মকার`, ID `DUR@900`, পাসওয়ার্ড `password`।
4. ডেমো সদস্যদের পাসওয়ার্ড:
   - সায়ন কোলে — `DUR002` / `Durga@1002`
   - সস্তিক কর্মকার — `DUR003` / `Durga@1003`
   - হমাংস মালিক — `DUR004` / `Durga@1004`
   - অরিত্র মালিক — `DUR005` / `Durga@1005`

## ফাইলগুলোর কাজ
- `Index.html`: লগইন
- `Dashboard.html`: সদস্য ও অর্থের সারাংশ
- `Member.html`: সদস্য খোঁজা, অ্যাডমিনের সদস্য যোগ/সম্পাদনা/সক্রিয়-নিষ্ক্রিয়
- `Profile.html`: সদস্য প্রোফাইল
- `Chatting.html`: Local Storage-ভিত্তিক ডেমো গ্রুপ চ্যাট
- `Gallery.html`: ডেমো ছবি/ভিডিও যোগ ও ডাউনলোড
- `Bills.html`: বছরভিত্তিক আয়-ব্যয়ের হিসাব
- `Reports.html`: রিপোর্ট ও CSV এক্সপোর্ট
- `Admin.html`: অ্যাডমিন শর্টকাট
- `Setting.html`: পরিচিতি, লোগো, কাস্টম ফিল্ড, চ্যাট নাম ও JSON ব্যাকআপ
- `data.json`: প্রাথমিক ডেটার নমুনা; ব্রাউজার সরাসরি এই ফাইলে পরিবর্তন লিখতে পারে না।
- `js/data-service.js`: ডেটা সার্ভিস ও Local Storage।
- `js/app.js`: পেজের UI ও ইন্টারঅ্যাকশন।
- `assets/`: লোগো।

## সদস্য যোগ/পরিবর্তন
অ্যাডমিন হিসেবে লগইন করে `Member.html` খুলুন। “নতুন সদস্য” দিয়ে সদস্য যোগ করুন। নাম, ID, পাসওয়ার্ড, দায়িত্ব, জন্মতারিখ, চাঁদা, ঠিকানা, মোবাইল ও ছবি যোগ করা যায়। সদস্যকে সক্রিয়/নিষ্ক্রিয়ও করা যায়।

## সেটিংস
অ্যাডমিন হিসেবে লগইন করে `Setting.html` খুলুন। সাইটের নাম, মূলমন্ত্র, ফুটার ও লোগো পরিবর্তন করা যায়; কাস্টম ফিল্ড তৈরি করা যায়; JSON ব্যাকআপ নেওয়া বা ইমপোর্ট করা যায়। ডেমো সেটিংস পাসওয়ার্ড `AK@2026#`। সেটিংস পেজে আলাদা পাসওয়ার্ড যাচাই রয়েছে। এটি ক্লায়েন্ট-সাইড ডেমো যাচাই, প্রকৃত নিরাপত্তা নয়।

## JSON ইমপোর্ট/এক্সপোর্ট
`Setting.html` → JSON এক্সপোর্ট। ইমপোর্ট করলে বর্তমান ডেটা প্রতিস্থাপিত হবে, তাই আগে ব্যাকআপ নিন। `data.json` হলো প্রাথমিক seed; পরিবর্তন Local Storage-এ থাকে।

## এখন ডেমো হিসেবে কাজ করে
- নাম, ID ও পাসওয়ার্ড যাচাই; অ্যাডমিন/সদস্য UI পার্থক্য
- সদস্য তালিকা, সার্চ, প্রোফাইল, সদস্য যোগ/সম্পাদনা/নিষ্ক্রিয়
- ডেমো চ্যাট এবং অ্যাডমিনের মেসেজ edit/delete
- গ্যালারি ফাইল যোগ/মুছে ফেলা/ডাউনলোড (ছোট ফাইলের জন্য)
- বছরভিত্তিক আর্থিক রেকর্ড, সারাংশ ও CSV রিপোর্ট
- লোগো/সাইটের নাম/মটো পরিবর্তন, custom field, JSON backup/import
- মোবাইল-উপযোগী লেআউট

## সীমাবদ্ধতা ও নিরাপত্তা
এটি প্রোটোটাইপ/ডেমো। Local Storage শুধু বর্তমান ব্রাউজার ও ডিভাইসে ডেটা রাখে। HTML/JavaScript-এ থাকা ডেমো পাসওয়ার্ড গোপন নয়; ব্যবহারকারীরা কোড ও ডেটা দেখতে বা বদলাতে পারেন। আর্থিক ডেটা ও সদস্যের তথ্যের জন্য এটিকে একমাত্র নিরাপদ ব্যবস্থা হিসেবে ব্যবহার করবেন না। লাইভ চ্যাট, বহু-ডিভাইসে সিঙ্ক, নিরাপদ অথেনটিকেশন, স্থায়ী ফাইল আপলোড ও অনুমতি নিয়ন্ত্রণের জন্য ব্যাকএন্ড প্রয়োজন।

## ভবিষ্যতে Supabase যুক্ত করা
1. Supabase প্রজেক্ট তৈরি করুন।
2. `members/profiles`, `gallery`, `chat_messages`, `chat_group_members`, `financial_years`, `contributions`, `expenses`, `donations`, `custom_fields`, `site_settings`, `audit_logs`-এর উপযুক্ত টেবিল ও সম্পর্ক তৈরি করুন।
3. Supabase Auth দিয়ে পরিচয় যাচাই করুন এবং role/permission নির্ধারণ করুন।
4. প্রতিটি টেবিলে Row Level Security (RLS) নীতি লিখুন; সদস্যদের আর্থিক পরিবর্তন ও অ্যাডমিন কাজ সার্ভার-সাইডে আটকে দিন।
5. `js/data-service.js`-এ Local Storage adapter-এর বদলে Supabase adapter যুক্ত করুন।
6. ছবি/ভিডিও Supabase Storage-এ রাখুন; লাইভ চ্যাটের জন্য Realtime ব্যবহার করা যেতে পারে।
7. `service_role` key কখনো ব্রাউজার কোডে রাখবেন না; কেবল public anon key ব্যবহার করুন, তাও সঠিক RLS-এর সঙ্গে।
8. JSON ডেটা আমদানির আগে schema validation ও backup করুন।

## নোট
এই প্রজেক্ট Supabase-এ সংযুক্ত নয় এবং অনলাইনে প্রকাশিত নয়। ZIP Extract করে লোকালি চালানো যায়।
